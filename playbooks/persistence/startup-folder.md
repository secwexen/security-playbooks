# Startup Folder Persistence

## Purpose

This playbook provides a structured workflow for investigating suspicious Windows Startup Folder persistence.

Startup Folders are legitimate Windows mechanisms that can automatically launch applications when a user logs on. They can also be abused to maintain persistence by placing unauthorized executables, scripts, shortcuts, or other startup items in the appropriate folder.

The objective is to determine whether the startup item is legitimate, suspicious, or malicious and whether it is associated with additional unauthorized activity.

## MITRE ATT&CK

| Technique | Name                               | Relevance                                                                        |
| --------- | ---------------------------------- | -------------------------------------------------------------------------------- |
| T1547.001 | Registry Run Keys / Startup Folder | Relevant when a Startup Folder item is used to establish or maintain persistence |

Additional ATT&CK techniques should only be mapped when supported by the observed behavior.

## Trigger Conditions

Start this playbook when one or more of the following conditions are observed:

- An unexpected file is created in a Windows Startup Folder.
- An unknown executable, script, or shortcut is configured to run at logon.
- A Startup Folder is modified by an unexpected process or account.
- A startup item references an unusual or unknown payload.
- Startup execution is associated with suspicious process or network activity.
- Threat hunting identifies anomalous Startup Folder persistence.

## Scope

The investigation should consider:

- affected host;
- associated user;
- Startup Folder path;
- startup item name;
- item type;
- item target;
- file hash;
- file timestamps;
- creating process;
- modifying account;
- parent process;
- child processes;
- user logon events;
- command line;
- file activity;
- network activity;
- DNS activity;
- related alerts;
- additional affected hosts.

## Common Startup Locations

Common Windows Startup Folder locations include user-specific and system-wide startup locations.

Examples include:

```text
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
%ProgramData%\Microsoft\Windows\Start Menu\Programs\StartUp
```

The exact path may vary by Windows configuration, environment, or user context.

Do not treat the presence of a file in a Startup Folder as malicious by itself. The file, its origin, target, and execution behavior must be evaluated in context.

## Investigation Procedure

### Step 1 — Identify the Alert

Determine:

- detection source;
- alert identifier;
- detection timestamp;
- affected host;
- associated user;
- Startup Folder path;
- startup item;
- detection severity;
- detection reason.

Preserve the original alert context before modifying or removing the startup item.

### Step 2 — Identify the Startup Item

Collect:

- filename;
- full path;
- file type;
- target path where applicable;
- file hash;
- creation time;
- modification time;
- digital signature where applicable.

Determine whether the item belongs to known and approved software.

### Step 3 — Review File Context

Determine:

- which process created the file;
- which account created it;
- creation timestamp;
- preceding process activity;
- related file operations;
- related downloads or archive extraction.

Correlate file creation with software installation, updates, administrative activity, or other expected changes.

### Step 4 — Review Startup Payload

Review the executable, script, shortcut, or other startup item.

Collect:

- target executable;
- target script;
- command line;
- arguments;
- working directory;
- file hash;
- signature information;
- source location.

Pay particular attention to payloads stored in:

- temporary directories;
- user-writable locations;
- hidden directories;
- unusual application data locations;
- paths associated with suspicious downloads.

A shortcut or script should be investigated based on its target and execution behavior rather than its file type alone.

### Step 5 — Review Logon Execution

Correlate the startup item with:

- user logon events;
- process creation;
- parent-child relationships;
- command-line telemetry;
- child processes.

Determine whether the startup item executed and whether it resulted in additional suspicious activity.

### Step 6 — Review Network Activity

Determine whether the startup payload or its child processes generated network activity.

Collect:

- destination IP;
- destination domain;
- destination port;
- protocol;
- DNS requests;
- connection timestamps.

Investigate unexpected communication with suspicious or unapproved infrastructure.

### Step 7 — Determine Persistence Scope

Search the environment for:

- same startup item;
- same path;
- same target;
- same file hash;
- same command line;
- same account;
- same network destination.

Determine:

- number of affected hosts;
- number of affected users;
- first observed item creation;
- latest observed execution;
- whether the startup item remains present.

### Step 8 — Determine Investigation Outcome

Classify the activity as:

- **Benign**
- **Suspicious**
- **Malicious**
- **Inconclusive**

Document the evidence supporting the classification.

## Evidence to Collect

| Evidence       | Description                                      |
| -------------- | ------------------------------------------------ |
| Alert          | Detection source, ID, severity, timestamp        |
| Host           | Hostname, IP address, operating system           |
| User           | Associated user or account                       |
| Startup Folder | Path and scope                                   |
| Startup Item   | Filename, type, target, metadata                 |
| File Hash      | SHA-256 or available hash                        |
| Signature      | Digital signature information where available    |
| File Creation  | Creating process, account, and timestamp         |
| Logon          | Relevant user logon events                       |
| Process        | Startup-related process activity                 |
| Process Tree   | Parent and child processes                       |
| Command Line   | Startup and child-process command lines          |
| Files          | Created, modified, downloaded, or executed files |
| Network        | Related network connections                      |
| DNS            | Related DNS activity                             |
| Scope          | Other affected hosts and users                   |
| Detections     | Related security alerts                          |

## Decision Criteria

### Benign

Classify the activity as **benign** when:

- the startup item belongs to approved software;
- creation was expected;
- the source and target are trusted;
- the associated process is legitimate;
- the startup behavior is consistent with normal application operation;
- no suspicious follow-on activity is identified.

Document the operational justification before closing the alert.

### Suspicious

Classify the activity as **suspicious** when:

- the startup item is unexpected;
- the source or creator is unclear;
- the payload is unknown;
- the target path is unusual;
- the startup item points to a user-writable or temporary location;
- related process or network activity is abnormal;
- additional investigation is required.

Continue investigation and collect additional evidence.

### Malicious

Classify the activity as **malicious** when sufficient evidence indicates:

- unauthorized Startup Folder persistence;
- confirmed malicious executable or script;
- malicious shortcut target;
- confirmed payload execution;
- command-and-control communication;
- credential access;
- lateral movement;
- other confirmed malicious behavior.

Escalate to the appropriate incident-response workflow.

### Inconclusive

Use **inconclusive** when available evidence is insufficient to determine whether the Startup Folder item is legitimate or malicious.

Document:

- evidence collected;
- evidence unavailable;
- additional telemetry required.

## Escalation

Escalate the investigation when:

- malicious Startup Folder persistence is confirmed;
- multiple hosts contain the same suspicious item;
- the startup payload is associated with known malware;
- credential compromise is suspected;
- lateral movement is identified;
- command-and-control activity is observed;
- a privileged or business-critical account is affected.

## Response Guidance

For confirmed malicious Startup Folder persistence:

1. Preserve file, process, logon, and network evidence.
2. Identify all affected hosts and accounts.
3. Determine whether the startup item is still present.
4. Follow the organization's endpoint containment procedure.
5. Search for related files, hashes, paths, command lines, and persistence mechanisms.
6. Investigate additional persistence mechanisms.
7. Follow authorized startup-item remediation procedures.
8. Review possible credential exposure.
9. Escalate confirmed compromise to incident response.
10. Document the investigation timeline and remediation actions.

Do not immediately delete or modify the startup item before required evidence preservation has been completed.

## Validation

The playbook should be validated against approved Startup Folder fixtures, file-system telemetry, user logon events, process creation events, endpoint telemetry, and controlled persistence scenarios.

Validation should confirm that:

- Startup Folder locations can be identified;
- startup item creation can be detected;
- creating processes and accounts can be correlated;
- startup payloads can be analyzed;
- logon and process execution can be correlated;
- related file and network activity can be investigated;
- persistence scope can be determined;
- legitimate startup items can be distinguished from malicious persistence;
- escalation criteria produce consistent outcomes.

## Safety

This playbook is intended for defensive security operations, security validation, controlled laboratory environments, and authorized testing only.

Startup Folder modifications should only be performed in approved testing or administrative environments. Do not modify or remove startup items on production systems outside authorized procedures.
