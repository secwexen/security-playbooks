# Detection Coverage Summary

## Overview

This report summarizes the MITRE ATT&CK detection coverage provided by the detection rules registered in this repository.

Coverage metrics are generated using:

- `detection-rules/registry.yaml`
- `detection-rules/mappings/mitre-mapping.yaml`

The registry is the authoritative source for rule inventory, while the MITRE mapping file is the authoritative source for ATT&CK technique mappings.

## Unmapped Detection Rules

Six registered detection rules currently have no explicit ATT&CK technique mapping in the authoritative mapping dataset.

These rules remain included in coverage calculations. No technique mappings are inferred automatically.

## Coverage Scope

This report represents coverage within the repository's explicitly defined ATT&CK mapping dataset.

It does not represent complete MITRE ATT&CK Enterprise coverage or the percentage of all ATT&CK techniques detected by the repository.

### Coverage Improvement Assessment

Historical changes demonstrate improvements in mapping specificity, rule inventory coverage and metadata consistency.

The mapping of PowerShell activity was refined from T1059 to T1059.001. Additional evidence-supported mappings were introduced for LSASS access and obfuscated PowerShell detection.

The previous T1110 mapping for Suspicious Login was removed during the evidence-based mapping review. No unsupported replacement mapping was introduced.

Historical mapping records do not provide a consistent rule inventory baseline for every reporting period. Therefore, a reliable historical coverage percentage comparison cannot be calculated from the available records.

### Tracking and Validation

Future coverage changes must be evaluated against:

- `detection-rules/registry.yaml`
- `detection-rules/mappings/mitre-mapping.yaml`

Coverage metrics are generated by:

- `tools/reports/coverage_report.py`

Historical changes are traceable through Git commit history.

New mappings must be supported by detection evidence and validated against the authoritative ATT&CK mapping source.

Coverage improvements and mapping metadata improvements must be tracked separately.
